## 1. Purpose and control
This document proposes requirement-level verification criteria to replace empty or generic placeholders in the working register. These criteria are derived from the candidate statements and source summaries; they are not source quotations, approved acceptance thresholds, test implementations, or authorization to build. Existing criteria are preserved as candidate criteria and explicitly remain subject to approval.

## 3. Verification evidence required for each test
Each executed verification case should retain: test-case ID and version; requirement ID; source clause; preconditions; test data/fixture; steps or executable test reference; expected result; actual result; environment/build; timestamp; logs/artifacts; reviewer; pass/fail/blocked disposition; defect reference where applicable.

## 4. Rules for unresolved criteria
1. No numerical latency, recovery, loss, throughput or availability threshold is inferred. The Roadmap requires targets to be set before testing; the competent project authority must approve them.
2. Cryptographic algorithms, key custody products, database technology, distributed coordination and exact schema formats remain unselected unless an approved source/decision explicitly selects them.
3. A criterion that depends on an unresolved decision must be marked BLOCKED_BY_DECISION, not passed.
4. Tests of OTS/Bitcoin must not make emergency reception or attention dependent on external timestamp availability.
5. Concurrency tests must state the coordination scope; independent disconnected databases cannot be assumed to provide global single-spend guarantees.
6. A verifier must report integrity, authenticity, identity, UTXO continuity, temporal evidence, file integrity and chronology as separate results where applicable.

## 5. WP-0.7 closure limitations
This proposal improves testability planning but does not itself close WP-0.7. Closure still requires exact source-clause confirmation, semantic atomicity/overlap dispositions, final mandatory-vs-recommendatory classification, design constraint review, decision/gap disposition, source-link audit, phase-allocation review and LAEV acceptance.

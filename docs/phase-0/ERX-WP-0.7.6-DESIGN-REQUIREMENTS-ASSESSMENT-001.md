## 1. Purpose and limits
This record documents the design-assessment field for all 82 source candidates. It distinguishes functional, data, security, architectural, operational, interface, governance and verification design constraints. A category identifies the principal design concern; it does not select a technology, approve an architecture, convert a recommendation into a mandatory obligation, or authorize implementation.

The assessment is a source-candidate-level screening. Child-level review of the 107 individually identified records remains necessary, particularly where a compound source candidate was decomposed into independent obligations.
